# clipperyt UX plan (proposal, 2026-11-19)

The visual style is settled (control room: tally red = on air, amber = waiting, teal = clipping).
This plan is about **flows**: what you do with the app, where it's slow or confusing today, and what
to change. It's ordered by how often you do each thing.

## How the app is used

| # | Job to be done | When / where | Today |
|---|---|---|---|
| 1 | Review last night's clips, pick the good ones, title them, post | Every morning, mostly on the **phone** | Clips tab is a grid of small players. Nothing says what's new. No way to mark a clip kept, skipped or posted. Titles are behind a button on each card. |
| 2 | Check that everything is fine | Before bed, any time | The Jobs page shows the jobs. Problems are spread around: failed jobs, the cookies warning, a missing drive, missing libass, low disk, and some only appear on the System tab. |
| 3 | Add a channel or a stream link | Occasionally | You have to know which box is which (YouTube *handle*, Twitch *login*, Kick *slug*), set "record video from", and switch between Watch and One link. |
| 4 | Fix a session (failed clips, a missed moment, a re-make) | When something's off | The session page has 8 buttons in one row. You can't see *where* in the stream the moments are, and you can't make a clip at a time you choose. |
| 5 | Tune settings | Rarely, but painful | One long page with about 45 fields. Technical names (bucket seconds, whisper binary) sit next to the things you actually change. You can't see what a change would do before re-making clips. |

## Proposal

### 1. Review: a morning inbox (biggest win)

The Clips tab becomes **Review**, opened by default when there are new clips.

```
┌──────────────────────────────┐   phone: one clip at a time, full height
│  12 new · 4 kept · 31 posted │   swipe up / down = next / previous
│ ┌──────────────────────────┐ │   desktop: J / K, Space = play, K = keep, S = skip
│ │                          │ │
│ │       9:16 player        │ │
│ │                          │ │
│ └──────────────────────────┘ │
│ IShowSpeed · #3 at 01:12:40  │
│ Clip request ×6 · score 14   │
│ “bhai kya shot” / “omg ×40”  │
│                              │
│ Title  ▾ [Bhai ne police ko…]│  ← AI suggestions load as you open the clip (only if a key is set)
│ [Copy title] [Copy description]
│ [ Skip ]  [ Download ]  [Keep]│  ← big thumb-sized buttons
└──────────────────────────────┘
```

- Each clip has a state: **New → Kept / Skipped → Posted**, stored in the clip folder (`review.json`), so it survives reloads and devices.
- The tab badge shows the number of new clips. Filters: New · Kept · Posted · Skipped · All, plus channel.
- Skipped clips are kept, not deleted. Delete stays an explicit action.
- When YouTube upload exists (option A), **Post** sits next to Keep and marks the clip Posted with its link.

### 2. Needs attention: one strip, every problem, each with its fix

Shown at the top of every tab only when something is wrong, with an action button:

```
⚠ 3 things need attention
  • YouTube is blocking recording for Techno Gamerz       [Upload cookies]
  • 4 clips failed in ohnepixel (20261119-0247)           [Fix clips]
  • Recordings drive is 92% full (38 GB left, ~7 h)      [Free disk…]
```

Sources: failed jobs, waiting jobs with a recorder error, failed clips, missing cookies when YouTube asks, recordings drive missing or low, libass/whisper/deno missing, folders not writable. Replaces today's separate banners.

### 3. Add a channel or link: one smart box

```
[ Paste a channel or stream link…                          ] [Add]
  youtube.com/@IShowSpeed  →  Watch channel  YouTube · IShowSpeed
  + add Twitch / Kick for the same streamer (chat is combined)
```

- One input that understands `youtube.com/@x`, `/watch?v=`, `youtu.be/`, `twitch.tv/x`, `twitch.tv/videos/…`, `kick.com/x`, or a bare name.
- A channel link becomes **Watch**, and a video or stream link becomes **One link**, shown before you press Add.
- "Record video from" disappears: it's the first channel you add, and can be changed later on the job.

### 4. Session: a timeline with moments, and "clip here"

```
chat / min ▁▂▂▃▂▁▂▇█▅▂▂▁▁▂▃▂▂▁▁▂▂▆▃▂▁   (whole stream)
            ▲ #1        ▲ #2      ▲ #3 (clip request ×6)
            [====clip====]
            00:41:10                          02:13:55
[ Make a clip at 01:57:30 ]  ← click anywhere on the graph
```

- The whole stream's chat graph, with every moment and clip marked. Click a moment to play its clip. Click anywhere else to **make a clip there** (a manual clip, cut with the current settings).
- Actions shrink to one main button that depends on the situation (Fix N failed / Add clip-request clips / Re-make), plus a **More** menu: list moments, move, delete recording, delete session.

### 5. Settings: what people change, first

- A left-hand section list (phone: a dropdown): **Detection · Clips & captions · Output · Titles (AI) · Storage · Channels · Advanced**.
- Advanced fields are hidden by default: whisper binary, model path, bucket and baseline seconds, encoder, retry seconds.
- **Detection preview**: when you change multiplier, min messages or clip-request settings, show "on the last session this would make 7 clips (you have 4)" using the existing moments endpoint, so you can tune before re-making.
- Fields that differ from the default get a dot and a **Reset**.

### 6. Polish

- In-app confirm dialogs instead of the browser's `confirm()`. Delete clip moves it to a 7-day trash, with **Undo** in the toast.
- Buttons show progress (spinner + "Starting…") and can't be double-clicked.
- First run: a short checklist (add a channel · check tools · optional: cookies, AI key, recordings drive).
- Remember the last tab and filters per device.

## Phases

| Phase | What | Why first |
|---|---|---|
| 1 | Review inbox (states, one-at-a-time player, inline titles, keyboard/swipe) + Needs attention strip | Daily use, phone-first; problems found without hunting |
| 2 | Smart "add channel or link" box | Removes the most confusing form |
| 3 | Session timeline + manual "clip here" + slimmer actions | Fixes and misses become easy |
| 4 | Settings reorganisation + detection preview | Tuning without trial and error |
| 5 | Polish (dialogs, undo, progress, onboarding) | Rough edges |

YouTube posting (option A) plugs into Phase 1's Review screen as a **Post** button once the Google setup is done.

## Non-goals

- No change to recording or clipping behaviour or timing rules.
- No external UI libraries or web fonts: it stays one offline HTML file.
- No AI calls except when you press a button.
